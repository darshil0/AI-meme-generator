# AI Meme Generator 🤖

**Your personal AI-powered meme factory. Create viral-worthy memes in seconds with the power of generative AI.**

This interactive web application allows you to create hilarious memes by combining images with AI-generated captions. Upload your own picture or choose from a library of popular templates, and let the Gemini AI suggest witty and relevant captions tailored to the image.

## ✨ Features

### 🖼️ Flexible Image Options

- Upload your own image files (JPG, PNG, GIF, WebP) – up to 10MB with client-side validation
- Select from a curated list of 13+ popular, trending meme templates
- Save your uploaded images as custom, reusable templates
- Search through templates with real-time filtering
- Template caching for faster loading

### 🧠 Magic AI Captions

- Click the "Magic Captions" button to get 5 unique, funny captions generated by Google's Gemini AI (using `gemini-2.0-flash` model)
- The AI analyzes the image content (or template name) to provide contextually relevant suggestions
- Refine AI suggestions by providing a custom tone:
  - **Humorous** – Classic funny memes
  - **Sarcastic** – Witty and ironic
  - **Wholesome** – Heartwarming and positive
  - **Absurd** – Random and surreal
  - **Dark** – Edgy humor
- Add optional context to guide caption generation
- Built-in error handling with user-friendly fallback messages on API failures

### ✏️ Powerful Text Editor

- Add unlimited text layers to your meme
- Customize each layer with:
  - Font size (10–200px)
  - Font color (full color picker)
  - Outline color for classic meme look
  - Text blur effect (0–10px)
  - Vertical positioning (0–100%)
- Reorder layers with up/down controls
- Select and edit individual layers

### 🎨 Image Filters

- Apply filters to change the mood:
  - None (original)
  - Grayscale
  - Sepia
  - Invert
  - Blur
  - Brightness
  - Contrast

### 💾 Session Management

- **Save Work**: Save your entire meme creation (image, text layers, filters, settings) to browser's durable storage using IndexedDB
- **Load Work**: Resume a previous editing session with a single click
- State persistence across browser sessions with IndexedDB for high-capacity storage (typically 50MB+ depending on browser)
- Custom templates saved permanently using `idb-keyval`
- Backward compatibility with older LocalStorage formats

### 🚀 Export & Share

- Download your final meme as a high-quality JPEG file
- Quality options: High (95%), High (92%), Medium (75%), Low (50%)
- Copy the meme directly to your clipboard to easily paste and share (with visual feedback)
- Automatic error handling for storage and clipboard operations

## 🧠 How It Works

The core of this application is its integration with the **Google Gemini API**. When a user requests "Magic Captions," one of two things happens:

1. **If an image is uploaded:** The application sends the image data (as a base64 string) and the selected tone/context to the Gemini model via a secure backend proxy. The model analyzes the visual content and generates captions based on its understanding of the image.

2. **If a template is selected:** The application sends the name of the template (e.g., "Distracted Boyfriend") to the model, which uses its vast knowledge of internet culture to generate appropriate captions for that specific meme format.

The AI is prompted to return results in structured JSON format, which the application then parses and displays as clickable suggestions. The service includes robust error handling, input sanitization, and CORS protection to ensure safe, reliable responses.

## 🛠️ Tech Stack

- **Framework:** [Angular](https://angular.dev/) (v21.0, Zoneless – new rendering pipeline without zone.js)

  - Inter (UI)
  - **Anton** (Meme text – primary)
  - Impact (Meme text – fallback)

## 🚀 Getting Started

### Prerequisites

**System Requirements:**
- Node.js (v18.10 or higher)
- npm (v9+) or yarn (v3+)

**For Backend Image Processing (if using local canvas rendering):**
- Cairo (system library) – required for the optional `canvas` package
  - **macOS:** `brew install cairo`
  - **Ubuntu/Debian:** `sudo apt-get install libcairo2-dev`
  - **Windows:** Included via `node-gyp` (requires Visual Studio Build Tools or equivalent)

**API Requirements:**
- Google Gemini API key (obtain from [Google AI Studio](https://aistudio.google.com/app/apikey))
- Free tier includes 60 API calls per minute

### Installation

1. Clone the repository:

```bash
git clone <repository-url>
cd ai-meme-generator
```

2. Install root dependencies:

```bash
npm install
```

3. Install backend dependencies separately:

```bash
cd server && npm install && cd ..
```

4. **Configure API Keys** (Critical for functionality)

**Development Setup:**

Create a `.env` file in the `server/` directory (never commit this file):

```env
GEMINI_API_KEY=your_actual_gemini_api_key_here
ALLOWED_ORIGIN=http://localhost:4200
NODE_ENV=development
PORT=4000
```

The backend will read this file and never expose the API key to the client.

**Production Setup:**

Use your platform's environment variable management (e.g., GitHub Secrets, Vercel Env Vars, Railway, Render environment settings). Never store API keys in code, `.env` files, or committed files.

```env
GEMINI_API_KEY=your_production_key
ALLOWED_ORIGIN=https://yourdomain.com
NODE_ENV=production
PORT=4000
```

## 🏃 Running the Application

### 1. Start the Backend (Gemini Proxy Server)

The backend service lives in the `server/` directory and handles:
- Secure communication with the Google Gemini API (API key lives **only** on the server)
- Proxying external meme template images to avoid CORS issues
- Input validation and rate limiting

**Terminal 1 – Backend:**

```bash
cd server

# Set environment variable (varies by OS)
# macOS/Linux:
export GEMINI_API_KEY="your_real_gemini_key"
npm run dev

# Windows (PowerShell):
$env:GEMINI_API_KEY="your_real_gemini_key"
npm run dev

# Or use a .env file as shown above
npm run dev
```

The backend will start on `http://localhost:4000`.

### 2. Start the Angular Frontend

**Terminal 2 – Frontend:**

In a new terminal, from the project root (not the `server/` directory):

```bash
npm run dev
```

The application will be available at `http://localhost:4200`. All `/api/*` requests are automatically proxied to the backend via `proxy.conf.json`.

**Verify both are running:**
- Frontend: http://localhost:4200 (loads the UI)
- Backend: http://localhost:4000/health (should return OK)

### 3. Testing

Run the test suite:

```bash
npm run test
```

Run tests in watch mode (recommended during development):

```bash
npm run test:watch
```

Generate coverage report:

```bash
npm run test:coverage
```

## 🌐 Deployment

### Architecture Overview

This project consists of two independently deployable services:

1. **Backend (`server/`)** – Node.js/Express API server (handles API keys, rate limiting, CORS)
2. **Frontend (`dist/`)** – Static SPA (Single Page Application)

Both should be deployed to handle production traffic, but can operate on separate infrastructure.

### Backend Deployment

Deploy the `server/` directory to any Node.js-compatible platform:

**Recommended Platforms:**
- [Render](https://render.com/) – Free tier available, auto-deploys from GitHub
- [Railway](https://railway.app/) – Simple, pay-as-you-go pricing
- [Cloud Run](https://cloud.google.com/run) – Serverless Google Cloud option
- [Heroku](https://www.heroku.com/) – Classic Node.js hosting (paid)
- [Fly.io](https://fly.io/) – Global deployment, good for low-latency APIs

**Required Environment Variables:**
- `GEMINI_API_KEY` – Your real Gemini API key (never hardcode; use platform secrets)
- `ALLOWED_ORIGIN` – Frontend URL (e.g., `https://your-domain.com`)
- `NODE_ENV` – Set to `production`
- `PORT` – Optional (defaults to 4000)

**Example deployment config for Render:**

```yaml
# render.yaml (in project root)
services:
  - type: web
    name: ai-meme-generator-api
    env: node
    region: oregon
    plan: free
    buildCommand: cd server && npm install
    startCommand: cd server && npm start
    envVars:
      - key: GEMINI_API_KEY
        scope: runtime
        sync: false
      - key: ALLOWED_ORIGIN
        value: https://your-frontend.com
      - key: NODE_ENV
        value: production
```

**Start command should be:** `cd server && npm start` (not `npm run dev`)

### Frontend Deployment

Build and deploy the `dist/` folder to a static host:

**Recommended Platforms:**
- [Vercel](https://vercel.com/) – Zero-config for SPAs, integrates with Render backend
- [Netlify](https://www.netlify.com/) – Excellent SPA support, easy redirects
- [GitHub Pages](https://pages.github.com/) – Free (public repo only)
- [AWS S3 + CloudFront](https://aws.amazon.com/cloudfront/) – CDN distribution for scale

**Build Command:**

```bash
npm run build
```

**Build Output Folder:** `dist/`

**Environment Configuration:**

Create `src/environments/environment.prod.ts` to point to your deployed backend:

```typescript
export const environment = {
  production: true,
  apiBaseUrl: 'https://api.your-domain.com'
};
```

Then reference this in your API service (verify your Angular service uses `environment.apiBaseUrl`).

### Architecture Patterns

**Option 1: Separate Domains (Recommended)**
```
Frontend: https://meme-gen.example.com
Backend:  https://api.meme-gen.example.com
```
- Update `ALLOWED_ORIGIN` on backend to match frontend domain
- Frontend's `proxy.conf.json` or environment config targets backend domain
- Easier to scale and manage independently

**Option 2: Single Domain with Reverse Proxy**
```
Frontend: https://meme-gen.example.com/
Backend:  https://meme-gen.example.com/api
```
- Use Nginx, Cloudflare Workers, or platform routing to split traffic
- `/api/*` routes to backend, `/` routes to frontend
- Requires backend to serve from `/api` path prefix

**Example Nginx config (Option 2):**
```nginx
server {
    listen 443 ssl;
    server_name meme-gen.example.com;

    # Frontend (static assets)
    location / {
        root /var/www/dist;
        try_files $uri $uri/ /index.html;
    }

    # Backend API
    location /api {
        proxy_pass http://backend-service:4000;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

## 🔒 Security Considerations

1. **API Key Management:**
   - Never commit `.env` files
   - Use `.env.example` as a template
   - Rotate API keys periodically
   - Monitor API usage in Google Cloud Console

2. **Image Upload Validation:**
   - Client-side: File type and size checks (10MB limit)
   - Server-side: Re-validate file type and size
   - Scan for malicious content or metadata before processing

3. **CORS Configuration:**
   - Backend enforces `ALLOWED_ORIGIN` check
   - Only your frontend domain can make API requests
   - No credentials in cross-origin requests

4. **Rate Limiting:**
   - Consider implementing per-user rate limiting on the backend
   - Gemini API has built-in quotas (60 req/min free tier)
   - Monitor for abuse patterns

## 🐛 Troubleshooting

### Cairo Installation Issues

If you encounter errors installing the `canvas` package (only needed for optional server-side image rendering):

**macOS:**
```bash
brew install cairo
npm install
```

**Ubuntu/Debian:**
```bash
sudo apt-get install build-essential libcairo2-dev
npm install
```

**Windows:**
Install Visual Studio Build Tools or Node.js build tools:
```bash
npm install --global windows-build-tools
npm install
```

### Backend Won't Start

**Error:** `EADDRINUSE: address already in use :::4000`
- Port 4000 is already in use. Kill the process or change `PORT` in `.env`:
  ```bash
  lsof -i :4000          # Find process ID
  kill -9 <PID>         # Kill process
  ```

**Error:** `GEMINI_API_KEY is not set`
- Ensure your `.env` file exists in `server/` or the environment variable is exported
- Verify the key is valid at [Google AI Studio](https://aistudio.google.com/app/apikey)

**Error:** `ECONNREFUSED` on backend API call
- Verify backend is running (`npm run dev` in `server/` directory)
- Check it's listening on `http://localhost:4000`

### Frontend Can't Reach Backend

- Verify backend is running on `http://localhost:4000`
- Check browser DevTools → Network tab for `/api/*` requests
- Confirm `proxy.conf.json` exists and is correctly configured
- Clear browser cache (`Ctrl+Shift+Delete` or `Cmd+Shift+Delete`)
- Check browser console for CORS errors (if so, verify `ALLOWED_ORIGIN` matches frontend URL)

### API Rate Limiting

If you hit Gemini API rate limits (60 requests/minute free tier):
- The frontend will display an error message
- Wait a moment before retrying
- Consider upgrading your Gemini API plan for production use
- Implement request queuing or caching on the backend

### Session Storage Not Working

If saved memes aren't persisting:
- Check browser storage limits (IndexedDB can fail on low disk space)
- Try clearing browser cache and reload the page
- Check browser console (DevTools → Console) for storage errors
- Firefox: `about:preferences#privacy` → Clear Storage
- IndexedDB size varies by browser (typically 50MB+ or unlimited)

### Image Upload Fails

- Ensure file is JPG, PNG, GIF, or WebP format
- Ensure file is under 10MB
- Check browser console for validation errors
- Verify backend `/api/captions` endpoint is responding
